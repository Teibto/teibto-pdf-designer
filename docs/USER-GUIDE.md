# คู่มือผู้ใช้ — PDF Layout Designer

เอกสารนี้สำหรับคนที่ **ใช้** product บน account NetSuite จริง อ่านแล้วพิมพ์เอกสาร ออกแบบเทมเพลต และตั้งค่าให้ account ได้เอง. คนที่จะแก้โค้ดอ่าน [`RUNBOOK.md`](RUNBOOK.md) แทน · คนที่จะติดตั้ง engine เข้า account ใหม่อ่าน [`engine/DEPLOYMENT.md`](../engine/DEPLOYMENT.md).

เจอปัญหาระหว่างทาง ดู [`TROUBLESHOOTING.md`](TROUBLESHOOTING.md) ซึ่งเรียงตามอาการที่เห็นบนจอ.

| บทบาท | อ่านส่วนไหน |
|---|---|
| พนักงานที่ออกเอกสารให้ลูกค้า | [พิมพ์เอกสาร](#พิมพ์เอกสาร) |
| Consultant ที่ทำเทมเพลตให้ลูกค้า | [ออกแบบเทมเพลต](#ออกแบบเทมเพลต) |
| ผู้ดูแลระบบ NetSuite ของ account | [ตั้งค่า account](#ตั้งค่า-account) |

## พิมพ์เอกสาร

### ปุ่มบนหน้า record

เปิดเอกสารในโหมด View (ไม่ใช่ Edit) แล้วดูแถบปุ่มด้านบน:

| ปุ่ม | ได้อะไร |
|---|---|
| **Print PDF** | เปิด PDF ในแท็บใหม่ พร้อมสั่งพิมพ์ต่อจากเบราว์เซอร์ |
| **Download PDF** | ดาวน์โหลดเป็นไฟล์ลงเครื่อง |
| **Design PDF** | เปิดดีไซเนอร์พร้อมข้อมูลของเอกสารใบนี้ (สำหรับ consultant) |
| **PDF Template** + **Print Selected Template** | เลือกเทมเพลตเฉพาะครั้ง ปุ่มนี้ขึ้นเมื่อ record type นั้นมีเทมเพลตมากกว่า 1 แบบ |

ปุ่มขึ้นกับ 10 ประเภทเอกสาร: ใบแจ้งหนี้ (`invoice`) · ใบลดหนี้ (`creditmemo`) · ใบเสนอราคา (`estimate`) · ใบสั่งขาย (`salesorder`) · ใบสั่งซื้อ (`purchaseorder`) · ใบกำกับภาษีอย่างย่อ/ขายสด (`cashsale`) · ใบตั้งหนี้ (`vendorbill`) · ใบรับคืน (`returnauthorization`) · ใบส่งสินค้า (`itemfulfillment`) · ใบเสร็จรับเงิน (`customerpayment`).

ไม่ระบุเทมเพลต ระบบใช้ **เทมเพลตค่าเริ่มต้นของ record type นั้น** เสมอ. ยังไม่มีใครตั้งค่าเริ่มต้นไว้ จะขึ้น `No template found` ([ทางแก้](TROUBLESHOOTING.md#no-template-found)).

### ชุดสำเนา

เอกสารหนึ่งใบพิมพ์ออกมาได้หลายชุดในไฟล์เดียว เช่น ต้นฉบับ + สำเนา ตามที่กฎหมายไทยกำหนดสำหรับใบกำกับภาษี. ชุดสำเนาตั้งไว้ที่ตัวเทมเพลต ไม่ใช่ตอนกดพิมพ์ ([ตั้งอย่างไร](#ชุดสำเนาของเทมเพลต)).

### พิมพ์หลายใบพร้อมกัน

หน้าจอ **พิมพ์เอกสารเป็นชุด** (Suitelet `PLD - Batch Print`) รวมหลายใบเป็น PDF ไฟล์เดียว:

1. เลือกประเภทเอกสารและช่วงวันที่ แล้วกด **ค้นหาเอกสาร** (แสดงได้สูงสุด 300 รายการต่อครั้ง ช่วงวันที่กว้างเกินให้แคบลง)
2. ติ๊กใบที่ต้องการ
3. กด **พิมพ์เป็นชุด** สำหรับชุดเล็ก หรือ **ส่งเข้าคิว (ชุดใหญ่)** สำหรับชุดใหญ่ (ครั้งละไม่เกิน 500 ใบ)

ชุดที่ส่งเข้าคิวต้องมี XML รวมหลังผูกข้อมูลไม่เกิน 8 MiB ด้วย หากเกินระบบจะแจ้งให้ลดจำนวน
เอกสารหรือสำเนาแล้วส่งใหม่; จำนวน 500 ใบเป็นเพดานรับงาน ไม่ใช่การรับประกันว่าทุกชุดจะมีขนาดพอดี.
พิมพ์ได้ไม่เกิน 20 สำเนาต่อเอกสาร. แบบและชื่อสำเนาจะยึดตามเวลาที่ส่งเข้าคิว; ถ้าแก้แบบภายหลัง
และต้องการใช้แบบใหม่ ให้ส่งงานใหม่. หากระบบแจ้งว่ามี default หลายรายการ ให้ผู้ดูแลเลือกเหลือ
หนึ่งรายการของประเภทเอกสารนั้นก่อนพิมพ์.

**พิมพ์เป็นชุด** ได้ไฟล์ทันที แต่จำกัดด้วยโควตาสคริปต์ของ NetSuite ราว 6 ใบต่อครั้งสำหรับใบแจ้งหนี้ (วัดจากของจริง ~160 units ต่อใบ). เกินโควตาระบบไม่ส่งไฟล์ที่ขาดใบให้ แต่ขึ้นหน้า **พิมพ์เป็นชุดไม่ครบ** บอกว่าใบไหนสำเร็จ ใบไหนล้มเหลว ใบไหนยังไม่ได้พิมพ์ พร้อมปุ่มสั่งพิมพ์ส่วนที่เหลือ.

**ส่งเข้าคิว (ชุดใหญ่)** สร้างไฟล์เบื้องหลังแล้วอีเมลลิงก์ให้ผู้สั่งพิมพ์ ไฟล์เก็บใน File Cabinet โฟลเดอร์ `pld-batch`. ย้อนดูไฟล์ที่เคยสร้างได้จากลิงก์ **ดูไฟล์ชุดที่สร้างไว้แล้ว** บนหน้าเดียวกัน.

## ออกแบบเทมเพลต

### เปิดดีไซเนอร์

เปิดได้ 2 ทาง และผลต่างกันที่ข้อมูลที่ใช้พรีวิว:

| เปิดจาก | ข้อมูลที่ผูกได้ | พรีวิวเห็นอะไร |
|---|---|---|
| ปุ่ม **Design PDF** บน record | ข้อมูลจริงของเอกสารใบนั้น | PDF จริงของใบนั้น |
| URL ของ Suitelet `PLD - PDF Designer` ตรง (ไม่มี record) | ข้อมูลตัวอย่างสังเคราะห์ | PDF จริงที่ใช้ข้อมูลสมมติ |

ทั้งสองทางพรีวิวผ่าน BFO ตัวเดียวกับที่พิมพ์จริง. ปุ่ม **ดาวน์โหลด PDF ที่แสดง** ได้ฉบับเดียวกับ
พรีวิว รวมการแก้ไขที่ยังไม่บันทึก; ต้องบันทึกก่อนสั่ง Print จาก transaction เพื่อใช้แบบที่แก้ล่าสุด.

ไม่มี record แล้วอยากผูก binding ให้กด **⬇ โหลดข้อมูลตัวอย่างจาก NetSuite** ในแผงข้อมูล จะได้เอกสารสมมติที่มีฟิลด์ครบตามที่ engine จ่ายจริง.

### บันทึกเข้า NetSuite

1. กด **⚙ ตั้งค่าการบันทึก** บนแถบเครื่องมือ
2. เลือก **ประเภทเอกสาร** ให้ตรงกับ record type ที่จะกดปุ่ม Print (ระบบจับคู่แบบตรงตัว เทมเพลตเดียวใช้ข้ามประเภทไม่ได้)
3. ติ๊ก **ตั้งเป็น default template ของ record type นี้** ถ้าต้องการให้ปุ่ม Print ใช้เทมเพลตนี้
4. กด **บันทึกเข้า NetSuite**

ก่อนบันทึก ระบบตรวจกับดักของ BFO ให้อัตโนมัติ. เจอข้อผิดพลาดที่จะทำให้เอกสารพิมพ์ไม่ออกหรือพิมพ์ออกมาว่าง จะ **ไม่บันทึก** และบอกว่าติดอะไร รายการเต็มพร้อมวิธีแก้ดูในกล่อง **🔶 NetSuite BFO**. คำเตือน (warning) ไม่บล็อกการบันทึก แต่แปลว่าหน้าตาบนกระดาษอาจไม่ตรงกับที่เห็นบนจอ.

### ชุดสำเนาของเทมเพลต

ตั้งจำนวนชุดและป้ายของแต่ละชุดในดีไซเนอร์ (เช่น `ต้นฉบับ / Original` และ `สำเนา / Copy`). ค่าเริ่มต้นของใบแจ้งหนี้คือ 2 ชุด. เทมเพลตอ้างป้ายผ่าน `${copy.label}` `${copy.th}` `${copy.en}` ซึ่งใช้ได้กับทุกประเภทเอกสาร.

### ประวัติเวอร์ชันและการกู้คืน

ทุกครั้งที่บันทึก ลบ หรือกู้คืน ระบบเก็บสำเนาของเทมเพลตไว้หนึ่งเวอร์ชัน พร้อมชื่อผู้แก้ บทบาท และเวลา.

1. เปิด **📁 เทมเพลต** แล้วไปแท็บ NetSuite
2. กด **🕘 ประวัติ** บนเทมเพลตที่ต้องการ
3. กด **กู้คืน** ที่เวอร์ชันที่ต้องการ

การกู้คืนเขียนเป็นเวอร์ชันใหม่เสมอ ประวัติเดิมไม่หาย จึงย้อนกลับไปกลับมาได้. เทมเพลตที่ถูกลบไปแล้วก็กู้กลับมาได้ แต่จะเป็น record ใหม่ที่ **ยังไม่ใช่ค่าเริ่มต้น** ต้องไปตั้งค่าเริ่มต้นเองก่อนปุ่ม Print จึงจะใช้.

ระบบเก็บ**เนื้อไฟล์** 20 เวอร์ชันล่าสุดต่อเทมเพลต. เวอร์ชันที่เก่ากว่านั้นยังบอกได้ว่าใครแก้เมื่อไหร่ แต่กู้คืนไม่ได้ ปุ่มกู้คืนจะถูกปิดพร้อมบอกเหตุผล.

### บทบาทที่แก้เทมเพลตไม่ได้

เห็นป้าย **🔒 อ่านอย่างเดียว** บนแถบเครื่องมือ แปลว่า role ที่ใช้อยู่เปิดดูและพิมพ์ได้ แต่บันทึกไม่ได้. ให้ผู้ดูแลระบบเพิ่ม role นี้ใน [Template Editor Roles](#สิทธิ์แก้ไขเทมเพลต).

## ตั้งค่า account

### ข้อมูลบริษัทและฟอนต์

ทุกเทมเพลตดึงชื่อบริษัท ที่อยู่ เลขประจำตัวผู้เสียภาษี โลโก้ และฟอนต์ จาก custom record `customrecord_pld_config` ที่เดียว. แก้ที่นี่ครั้งเดียวมีผลกับทุกเทมเพลตของ account.

ข้อบังคับ 2 ข้อที่พลาดแล้วเอกสารเสียเงียบ:

- **ฟอนต์ไทยต้องเป็น THSarabunPSK เท่านั้น** ห้ามใช้ THSarabunNew เพราะ BFO ไม่จัดตำแหน่งวรรณยุกต์ให้ สระและวรรณยุกต์จะลอยหลุดจากฐาน
- **ช่องฟอนต์และโลโก้ให้ใส่ file id ไม่ใช่ URL** URL ของ File Cabinet มี token ที่หมดอายุเมื่อไฟล์ถูกบันทึกซ้ำ แล้วตัวอักษรไทยจะหายทั้งใบโดยไม่มี error

ขั้นตอนเต็มรวมชื่อ field ทุกตัวอยู่ในหัวข้อ Company Config ของ [`engine/DEPLOYMENT.md`](../engine/DEPLOYMENT.md).

### สิทธิ์แก้ไขเทมเพลต

เทมเพลตหนึ่งใบคุมหน้าตาเอกสารตามกฎหมายของทั้ง account การพิมพ์จึงเปิดให้ทุกคน แต่การ **แก้** จำกัดตาม role.

ใส่ internal id ของ role ที่แก้ได้ในช่อง **Template Editor Roles** (`custrecord_pld_cfg_editor_roles`) บน config record คั่นด้วย comma เช่น `1017,1042`. ดู internal id ได้ที่ Setup > Users/Roles > Manage Roles.

- Administrator แก้ได้เสมอ ไม่ต้องใส่
- **ช่องว่าง = เฉพาะ Administrator** ระบบตั้งใจให้เข้มไว้ก่อน ไม่ใช่เปิดให้ทุกคน
- สิทธิ์นี้เป็นระดับ account ไม่ผูก subsidiary เพราะเทมเพลตใช้ร่วมกันทั้ง account

### ตรวจว่า account รัน version อะไร

เปิด URL ของ Suitelet `PLD - PDF Renderer` แล้วต่อท้ายด้วย `&action=version` จะได้ JSON บอกเวอร์ชัน git sha และเวลาที่ deploy. ข้อมูลนี้ต้องแนบทุกครั้งที่แจ้งปัญหาเข้าทีม.

### ตรวจว่าใครแก้เทมเพลตไป

ดูได้ 2 ทาง:

- custom record `customrecord_pld_tpl_version` มีทุกการเปลี่ยนแปลงพร้อมผู้แก้ บทบาท และเวลา เก็บถาวรบน account
- Script Execution Log ของ Suitelet renderer มีบรรทัด `PLD template update` / `PLD template delete` / `PLD template rollback` และ `PLD template write denied` สำหรับคำขอที่ถูกปฏิเสธ (log หมดอายุตามนโยบายของ NetSuite ส่วน custom record ไม่หมด)

วิธีเปิด Execution Log อยู่ใน [`TROUBLESHOOTING.md`](TROUBLESHOOTING.md#เก็บข้อมูลก่อนแจ้งทีม).
