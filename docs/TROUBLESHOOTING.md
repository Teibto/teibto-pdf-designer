## No template found

**อาการ** กด Print PDF แล้วขึ้นข้อความ `No template found. Please specify tplid or set a default template for <record type>`

**สาเหตุ** record type นั้นยังไม่มีเทมเพลตที่ติ๊ก "เป็นค่าเริ่มต้น" ไว้. ปุ่ม Print ไม่ระบุเทมเพลต ระบบจึงหาค่าเริ่มต้นของ record type แบบตรงตัว.

**ทางแก้** เปิดดีไซเนอร์ โหลดเทมเพลตที่ต้องการใช้ กด **⚙ ตั้งค่าการบันทึก** เลือกประเภทเอกสารให้ตรง ติ๊กตั้งเป็น default แล้วบันทึก.

**กับดักที่เจอบ่อย** เทมเพลตเก่าบางใบถูกบันทึกไว้ด้วยประเภทเอกสารชื่อ `transaction` ซึ่งไม่ใช่ record type จริงของ NetSuite ระบบจึงหาไม่เจอตลอดไป. เปิดเทมเพลตนั้นแล้วเปลี่ยนเป็นประเภทที่ถูกต้อง (`invoice`, `salesorder`, …) แล้วบันทึกใหม่.

## สร้าง PDF ไม่สำเร็จ

**อาการ** กด Print แล้วได้หน้าภาษาไทยว่า "สร้าง PDF ไม่สำเร็จ" พร้อมรหัสอ้างอิงเช่น `PLD-ms08g03c-82xc`

**สาเหตุ** การ render ล้มเหลว. ข้อมูลบนเอกสารไม่ถูกแก้ไขใด ๆ.

**ทางแก้** กดลองพิมพ์อีกครั้งหนึ่งรอบ. ยังไม่ผ่านให้แจ้งทีม Teibto พร้อม **รหัสอ้างอิงบนหน้าจอ** ทีมเปิด log ของการพิมพ์ครั้งนั้นได้ตรง ๆ จากรหัสนี้. รายละเอียดทางเทคนิคซ่อนอยู่ใต้หัวข้อ "รายละเอียดทางเทคนิค" บนหน้าเดียวกัน ส่งมาด้วยจะช่วยได้มาก.

## ตัวอักษรไทยหาย

**อาการ** PDF ออกมาแต่บรรทัดภาษาไทยหายไปทั้งบรรทัด หรือกลายเป็นสี่เหลี่ยม ส่วนตัวเลขและอังกฤษยังอยู่ ไม่มี error ใด ๆ

**สาเหตุ** BFO โหลดไฟล์ฟอนต์ไม่ได้ แล้วทิ้ง glyph ไทยเงียบ ๆ. เกิดจาก 3 กรณี:

| กรณี | สังเกตจาก |
|---|---|
| ยังไม่ได้ตั้งฟอนต์ใน config ของ account | ดีไซเนอร์ขึ้นคำเตือนตอนบันทึกและในกล่อง BFO |
| ตั้งเป็น URL ที่ token หมดอายุ (มักเกิดหลัง deploy) | ค่าในช่องฟอนต์ขึ้นต้นด้วย `https://` และมี `h=` |
| ตั้งเป็น THSarabunNew แทน THSarabunPSK | สระและวรรณยุกต์ลอยหลุดจากฐาน เห็นชัดที่คำว่า "น้ำ" "ค่า" |

**ทางแก้** แก้ที่ `customrecord_pld_config` ของ account: ใส่ **file id** ของไฟล์ฟอนต์ (ไม่ใช่ URL) และไฟล์ต้องเป็น THSarabunPSK. ขนาดไฟล์ PDF เป็นตัวชี้วัดที่เร็วที่สุด เอกสารใบเดียวกันวัดจริงได้ 18,691 byte ตอนฟอนต์ถูกฝังครบ และเหลือ 5,442 byte ตอน token ของ URL ผิด.

**ใครแก้** admin ของ account ([ขั้นตอน](USER-GUIDE.md#ข้อมูลบริษัทและฟอนต์))

## ช่องจำนวนเงินว่าง

**อาการ** เอกสารพิมพ์ออก มีเลขที่ วันที่ ชื่อลูกค้าครบ แต่ช่องจำนวน ราคาต่อหน่วย ยอดรวม และบรรทัดตัวอักษร ว่างหมด

**สาเหตุ** เทมเพลตพยายามจัดรูปแบบตัวเลขเอง. ค่าทุกตัวที่ส่งถึงเทมเพลตเป็นข้อความเสมอ การสั่ง `?string("#,##0.00")` บนข้อความจึงคืนค่าว่างโดยไม่มี error.

**ทางแก้** ให้เทมเพลตพิมพ์ค่าที่ engine จัดรูปแบบมาแล้วตรง ๆ: `${record.totalText}` `${record.bahtText}` `${line.amountText}` `${line.quantityText}` `${line.rateText}`. เทมเพลตที่สร้างจากดีไซเนอร์รุ่นปัจจุบันจัดการให้แล้ว อาการนี้พบในเทมเพลตที่เขียน XML เอง.

## บางใบพิมพ์ไม่ออก

**อาการ** เอกสารส่วนใหญ่พิมพ์ได้ปกติ แต่บางใบพิมพ์ไม่ออกเลยทั้งใบ. ใบที่พังมักมีชื่อสินค้าหรือชื่อคู่ค้าที่มีเครื่องหมาย `&` เช่น "Laser & Inkjet" หรือ "A & B จำกัด"

**สาเหตุ** BFO อ่านผลลัพธ์ของเทมเพลตเป็น XML อีกชั้นหนึ่ง ค่าที่มี `&` หรือ `<` จึงทำให้ทั้งเอกสารพังตั้งแต่ขั้นอ่านไฟล์ ไม่ใช่แค่ช่องนั้นว่าง.

**ทางแก้** ทุก binding ที่ค่ามาจากข้อมูลต้องผ่าน `?xml` เช่น `${(record.entity!"")?xml}`. ดีไซเนอร์รุ่นปัจจุบันปล่อยให้อัตโนมัติและ**ปฏิเสธการบันทึก**ถ้าเจอ binding ที่ยังไม่ผ่าน. เทมเพลตที่เขียน XML เองต้องแก้ทีละจุด.

**ตรวจก่อนส่งมอบ** พรีวิวด้วยข้อมูลตัวอย่างในดีไซเนอร์หนึ่งครั้ง ข้อมูลชุดนั้นมี `&` อยู่ในชื่อสินค้าโดยตั้งใจ เทมเพลตที่ยังไม่ปลอดภัยจะพังตรงนั้นทันที.

## ฟิลด์ว่างเป็นบางช่อง

**อาการ** เอกสารพิมพ์ออกครบ แต่บางช่องว่างเปล่าทั้งที่ข้อมูลบน record มีอยู่

**สาเหตุ** เทมเพลตอ้างชื่อฟิลด์ที่ engine ไม่ได้จ่ายให้ record type นั้น. ระบบไม่ error เพราะ binding ทุกตัวมีค่าสำรองเป็นค่าว่าง.

**ทางแก้** เปิดกล่อง **🔶 NetSuite BFO** ในดีไซเนอร์ ระบบจะเตือนชื่อฟิลด์ที่อยู่นอกรายการที่ engine จ่ายจริง พร้อมบอกว่าจะเกิดอะไรขึ้น. เลือกฟิลด์จากรายการที่มีให้ หรือแจ้งทีม Teibto ให้เพิ่มฟิลด์นั้นเข้า engine.

## โลโก้ล้นหน้า

**อาการ** โลโก้ใหญ่ผิดสัดส่วน ล้นออกนอกกรอบ ดันบล็อกชื่อเอกสารตกหน้า และทับกล่องข้อมูลลูกค้าจนอ่านไม่ออก

**สาเหตุ** รูปถูกกำหนดขนาดด้านเดียว (เช่นกำหนดแต่ความกว้าง หรือใช้ `max-width`). BFO ย่อรูปก็ต่อเมื่อได้กล่องครบทั้งกว้างและสูง ให้ค่าด้านเดียวมันจะวาดขนาดจริงแล้วโดนตัดตามขอบหน้า.

**ทางแก้** กำหนดความกว้างและความสูงคู่กันเสมอ. ดีไซเนอร์ตรวจข้อนี้ให้ตอนบันทึกและปฏิเสธถ้าเจอรูปที่กำหนดด้านเดียว.

## สำเนาขึ้นป้ายผิด

**อาการ** พิมพ์ได้ 2 ชุดตามที่ตั้งไว้ แต่ทั้งสองชุดขึ้นป้าย "ต้นฉบับ" เหมือนกัน

**สาเหตุ** เทมเพลตอ่านป้ายจากฟิลด์บน record แทนที่จะอ่านจากชุดที่กำลังพิมพ์อยู่.

**ทางแก้** ให้เทมเพลตใช้ `${copy.label}` `${copy.th}` `${copy.en}` ซึ่ง engine ใส่ให้ทุกชุดที่พิมพ์ และใช้ได้กับทุกประเภทเอกสาร. ตรวจด้วยการพรีวิวแล้วดูให้ครบทุกหน้า ไม่ใช่ดูแค่หน้าแรก.

## บันทึกไม่ได้ ไม่มีสิทธิ์

**อาการ** กดบันทึกแล้วขึ้นว่า "บทบาทของคุณไม่มีสิทธิ์แก้ไขเทมเพลตเอกสาร (role …)" หรือเห็นป้าย **🔒 อ่านอย่างเดียว** ตั้งแต่เปิดหน้าจอ

**สาเหตุ** role ที่ใช้อยู่ไม่ได้อยู่ในรายการที่แก้เทมเพลตได้. การพิมพ์เอกสารไม่ถูกจำกัด แต่การแก้ถูกจำกัดโดยตั้งใจ เพราะเทมเพลตหนึ่งใบคุมเอกสารตามกฎหมายของทั้ง account.

**ทางแก้** ให้ admin ใส่ internal id ของ role นั้นในช่อง **Template Editor Roles** บน config record ([ขั้นตอน](USER-GUIDE.md#สิทธิ์แก้ไขเทมเพลต)). Administrator แก้ได้เสมอโดยไม่ต้องใส่.

## บันทึกไม่ได้ ติด lint

**อาการ** กดบันทึกแล้วขึ้นว่า "บันทึกไม่ได้ — เทมเพลตนี้จะพิมพ์ไม่ออกหรือพิมพ์ออกมาว่าง (N ข้อ)"

**สาเหตุ** ระบบตรวจเจอกับดักที่พิสูจน์แล้วว่าทำให้เอกสารเสีย จึงหยุดไว้ก่อนที่เทมเพลตเดิมบน account จะถูกเขียนทับ.

**ทางแก้** เปิดกล่อง **🔶 NetSuite BFO** ดูรายการเต็ม แต่ละข้อบอกอาการที่จะเกิดและวิธีแก้. แก้ครบแล้วกดบันทึกใหม่.

รายการที่ขึ้นเป็น **คำเตือน** ไม่บล็อกการบันทึก แต่แปลว่าผลบนกระดาษอาจไม่ตรงกับที่เห็นบนจอ ควรพรีวิวยืนยันก่อนส่งมอบ.

## กู้คืนไม่ได้

**อาการ** เปิดประวัติเวอร์ชันแล้วเห็นแถวเก่าอยู่ แต่ปุ่มกู้คืนถูกปิด หรือกดแล้วขึ้นว่าเวอร์ชันนั้นไม่มีเนื้อไฟล์ให้กู้คืนแล้ว

**สาเหตุ** ระบบเก็บเนื้อไฟล์ไว้ 20 เวอร์ชันล่าสุดต่อเทมเพลต เพื่อไม่ให้ข้อมูลบน account โตไม่มีเพดาน. เวอร์ชันที่เก่ากว่านั้นเหลือไว้เฉพาะร่องรอยว่าใครแก้เมื่อไหร่.

**ทางแก้** ไม่มี. ป้องกันด้วยการ export เทมเพลตเป็นไฟล์ JSON เก็บไว้เองก่อนแก้ครั้งใหญ่ และให้เทมเพลตหลักของลูกค้าอยู่ใน repo ผ่าน PR ไม่ใช่อยู่บน account อย่างเดียว.

## เซสชันหมดอายุ

**อาการ** ออกแบบอยู่แล้วกดบันทึก ขึ้นว่า "เซสชัน NetSuite หมดอายุหรือถูก redirect ไปหน้า login"

**สาเหตุ** ดีไซเนอร์เปิดค้างไว้นานจน session ของ NetSuite หมดอายุ.

**ทางแก้** เปิดหน้าดีไซเนอร์ใหม่จาก NetSuite แล้วบันทึกอีกครั้ง. งานที่ยังไม่ได้บันทึกจะยังอยู่ในหน้าเดิม ให้คัดลอก JSON ออกจากมุมมอง **⟨/⟩ JSON** ก่อนปิดหน้านั้น.

## พิมพ์เป็นชุดได้หน้าสรุป

**อาการ** เลือกไว้หลายใบ กดพิมพ์แล้วไม่ได้ไฟล์ แต่ได้หน้าสรุปบอกว่าใบไหนสำเร็จ ใบไหนล้มเหลว ใบไหนยังไม่ได้พิมพ์

**สาเหตุ** โควตาการประมวลผลต่อคำสั่งของ NetSuite หมดก่อนที่จะพิมพ์ครบทุกใบ. ระบบไม่ส่งไฟล์ที่ขาดใบให้โดยไม่บอก จึงขึ้นหน้าสรุปแทน.

**ทางแก้** กดปุ่มสั่งพิมพ์ส่วนที่เหลือบนหน้า **พิมพ์เป็นชุดไม่ครบ** หรือกลับไปกด **ส่งเข้าคิว (ชุดใหญ่)** เพื่อให้ระบบสร้างเบื้องหลังแล้วอีเมลไฟล์รวมมาให้. ชุดที่เกินราว 6 ใบควรส่งเข้าคิวตั้งแต่แรก.

ใบที่ล้มเหลวรายใบมีรหัสอ้างอิงกำกับ ใช้แจ้งทีมได้เหมือนกรณี [สร้าง PDF ไม่สำเร็จ](#สร้าง-pdf-ไม่สำเร็จ).

## ส่งเข้าคิวแล้วไม่ได้อีเมล

**อาการ** กดส่งเข้าคิวแล้วระบบตอบรับ แต่ไม่ได้อีเมลลิงก์ไฟล์

**สาเหตุ** งานเบื้องหลังยังไม่เสร็จ หรืออีเมลของผู้ใช้บน NetSuite ไม่ถูกต้อง หรืองานล้มเหลวทั้งชุด.

**ทางแก้** เปิดลิงก์ **ดูไฟล์ชุดที่สร้างไว้แล้ว** บนหน้าพิมพ์เป็นชุด ไฟล์ที่สร้างเสร็จอยู่ที่นั่นเสมอไม่ว่าอีเมลจะถึงหรือไม่. ไฟล์เก็บใน File Cabinet โฟลเดอร์ `pld-batch`. ยังไม่เห็นไฟล์หลังผ่านไปนาน ให้ admin ตรวจสถานะ Map/Reduce ที่ Setup > Scripting > Script Deployments.

## ปุ่มไม่ขึ้นบน record

**อาการ** เปิดเอกสารแล้วไม่เห็นปุ่ม Print PDF / Download PDF / Design PDF

**สาเหตุ** เรียงจากที่พบบ่อยที่สุด:

| สาเหตุ | ตรวจอย่างไร |
|---|---|
| อยู่ในโหมด Edit | ปุ่มขึ้นเฉพาะโหมด View |
| record type นั้นไม่อยู่ใน 10 ประเภทที่รองรับ | ดูรายการใน [`USER-GUIDE.md`](USER-GUIDE.md#ปุ่มบนหน้า-record) |
| script `PLD - Transaction Buttons` ยังไม่ได้ deploy บน account | Setup > Scripting > Scripts |
| role ที่ใช้อยู่ไม่มีสิทธิ์รัน Suitelet | ลองด้วย Administrator เทียบ |

## เก็บข้อมูลก่อนแจ้งทีม

แนบ 3 อย่างนี้ทุกครั้ง จะย่นเวลาหาสาเหตุได้มาก:

1. **รหัสอ้างอิง** บนหน้าจอที่ error (`PLD-…`)
2. **เวอร์ชันที่ account รันอยู่** เปิด URL ของ Suitelet `PLD - PDF Renderer` ต่อท้ายด้วย `&action=version`
3. **ประเภทเอกสารและเลขที่เอกสาร** ที่พิมพ์ไม่ออก

admin ของ account ดู log ของการพิมพ์ครั้งนั้นเองได้: เปิด `script.nl?id=<script id ของ renderer>` แล้วคลิกแท็บ Execution Log ในหน้า ค้นด้วยรหัสอ้างอิงหรือคำว่า `PLD render failed`.
